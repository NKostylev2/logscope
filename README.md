# LogScope — Локальный анализатор логов (MVP 0.2)

**LogScope** — легковесный локальный инструмент для синхронного анализа логов и метрик из нескольких независимых источников на единой временной шкале.

Главная цель — сопоставление событий во времени и сквозная трассировка инцидентов по Request ID / Correlation ID без отправки содержимого во внешние облачные сервисы.

---

## 1. Возможности и поддерживаемые форматы

- **Текстовые логи (`.txt`, `.log`, `jmeter.log`)**:
  - Автоматическое объединение многострочных сообщений и Java stack trace (`at ...`, `Caused by:`, `... more`).
  - Размер одного события ограничен 2000 строками (`MAX_EVENT_LINES`): более длинные блоки, а также файлы без распознаваемых временных меток, режутся на последовательные события (наследуют время, уровень и Request ID), поэтому потребление памяти не зависит от размера файла.
  - Сохранение диапазонов исходных номеров строк (`line_start`, `line_end`).
  - Определение уровней логирования: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`, `FATAL`. Неизвестный уровень сохраняется как `None` (не подменяется на `INFO`).
  - Распознавание идентификаторов: `request_id`, `correlation_id`, `trace_id`, `x-request-id`.

- **JMeter JTL (CSV)**:
  - Разбор по именам заголовков (независимо от порядка колонок): `timeStamp`, `elapsed`, `label`, `responseCode`, `responseMessage`, `success`, `failureMessage`, `threadName`, `Latency`, `Connect`, `URL`, `bytes`, `sentBytes`, `grpThreads`, `allThreads`.
  - Вычисление длительности сэмплера (`duration_ms = elapsed`) и времени окончания (`timeStamp + elapsed`).
  - Классификация статуса: неуспешные запросы (`success=false` или `responseCode >= 400`) помечаются как `ERROR`.

- **JMeter JTL (XML)**:
  - Потоковый разбор через `xml.etree.ElementTree.iterparse` с очисткой элементов (`elem.clear()`), что обеспечивает константное потребление памяти $O(1)$ при обработке файлов любого объёма.
  - Поддержка тегов `<httpSample>` и `<sample>`, извлечение URL, assertions и текста ошибок.
  - Устойчивость к пустым и повреждённым XML-файлам.

- **CSV-файлы мониторинга и метрик**:
  - Автоматическое определение разделителей (`,`, `;`, `\t`, `|`).
  - Определение временных колонок (`timestamp`, `time`, `datetime`, `start_time`, `epoch`).
  - Поддержка форматов времени: ISO 8601, RFC 3339, Docker nanoseconds (`2026-10-14T12:13:11.558648158Z`), даты с миллисекундами, epoch секунды (10 цифр), миллисекунды (13 цифр), микросекунды (16 цифр), наносекунды (19 цифр).
  - Защита от ложного распознавания произвольных чисел как времени: валидация диапазона 2000–2100 гг.

- **Кодировки**:
  - Приоритетная поддержка UTF-8 / UTF-8-BOM.
  - Контролируемый fallback для распространённых Windows-кодировок (`cp1251`, `latin-1`).

## 2. Архитектура и хранилище

- **Сервер**: FastAPI, запуск строго на `127.0.0.1`.
- **Индекс**: SQLite в режиме `WAL` (Write-Ahead Logging) с внешними ключами.
- **Потоковый импорт**: обработка генераторами чанками по 1000 записей без загрузки всего файла в RAM.
- **Инкрементальный импорт и защита от дубликатов**:
  - Быстрый отпечаток файла: `размер` + `mtime_ns` + хеш границ (первые 64 КБ + последние 64 КБ).
  - Неизменённые файлы пропускаются за доли миллисекунды.
  - При изменении файла старые записи удаляются и переиндексируются в транзакции.
  - Удалённые с диска файлы автоматически очищаются из индекса.
- **Фоновая индексация**:
  - Запуск задач без блокировки HTTP-запроса.
  - Прогресс в реальном времени (`%`, текущий файл, счётчики).
  - Поддержка отмены импорта пользователем.

---

## 3. Безопасность

- По умолчанию сервер слушает только локальный loopback `127.0.0.1`.
- Доступ к файлам строго ограничен каталогом `LOGSCOPE_ALLOWED_ROOT` (по умолчанию `./data/inbox`).
- Все пути проверяются через `pathlib.Path.resolve().is_relative_to(...)`, попытки обхода (`..`, симлинки, внешние диски) пресекаются ошибками 400/403.
- Каждый файл внутри импортируемой папки дополнительно проверяется после разрешения симлинков: файл, указывающий за пределы `LOGSCOPE_ALLOWED_ROOT`, пропускается со статусом `skipped` (`outside_allowed_root`) и не попадает в индекс.
- Экранирование вывода в браузере предотвращает XSS при просмотре сырых логов.
- Данные не передаются во внешние сервисы.

## 4. API Спецификация

### Источники

#### `GET /api/sources`
Список проиндексированных источников с агрегированными счётчиками и границами времени.
```json
[
  {
    "id": 1,
    "path": "M:\\dev\\logscope-mvp\\data\\inbox\\sample-app.log",
    "name": "sample-app.log",
    "size_bytes": 305,
    "event_count": 3,
    "min_time_ms": 1792045421190,
    "max_time_ms": 1792045421950,
    "parse_errors": 0,
    "unparsed_timestamps": 0,
    "status": "ok"
  }
]
```

#### `GET /api/sources/{source_id}`
Получить детали конкретного источника.

---

### Индексация

#### `POST /api/import/start` или `POST /api/import/path`
Запуск фоновой индексации папки.
```json
// Запрос:
{ "path": "./data/inbox" }

// Ответ:
{
  "status": "started",
  "folder": "M:\\dev\\logscope-mvp\\data\\inbox",
  "message": "Импорт запущен в фоновом режиме"
}
```

#### `GET /api/import/status`
Получение прогресса активной или последней задачи индексации.
```json
{
  "status": "running", // running, completed, cancelled, failed, idle
  "progress_percent": 65.5,
  "total_files": 20,
  "processed_files": 13,
  "current_file": "jmeter.jtl",
  "total_events_imported": 45000,
  "stats": { "imported": 10, "unchanged": 3, "error": 0, "skipped": 0, "deleted": 0 },
  "message": "Обработка..."
}
```

#### `POST /api/import/cancel`
Запрос отмены активной фоновой задачи импорта.

---

### События

#### `GET /api/events`
Выборка событий с фильтрацией, пагинацией и детерминированной сортировкой:
- `start_ms` (int): начало интервала (`timestamp >= start_ms`).
- `end_ms` (int): конец интервала (`timestamp < end_ms`).
- `source_id` (int): фильтр по одному источнику.
- `source_ids` (str): фильтр по нескольким источникам через запятую (например, `1,2,5`).
- `level` (str): уровень (`ERROR`, `WARN`, `INFO`, `DEBUG`, `UNKNOWN`).
- `q` (str): поиск подстроки в сообщении с безопасным SQL escaping. Регистронезависимый, в том числе для кириллицы (запросы с не-ASCII символами выполняются медленнее: примерно 1 с на 1 млн событий за один проход).
- `request_id` (str): точный поиск по Request ID.
- `limit` (int): 1..5000 (по умолчанию 500).
- `offset` (int): смещение пагинации.

```json
{
  "total": 1250,
  "limit": 500,
  "offset": 0,
  "items": [
    {
      "id": 142,
      "source_id": 1,
      "source_name": "sample-app.log",
      "timestamp_utc_ms": 1792045421190,
      "timestamp_ms": 1792045421190,
      "timestamp_raw": "2026-10-15 10:23:41.190",
      "level": "INFO",
      "message": "2026-10-15 10:23:41.190 INFO request_id=demo-7f31a2 Обработка заказа начата",
      "line_start": 1,
      "line_end": 1,
      "request_id": "demo-7f31a2",
      "duration_ms": null,
      "event_type": "log"
    }
  ]
}
```

#### `GET /api/events/{event_id}`
Полная информация о событии с распакованным объектом `fields_json`.

#### `GET /api/events/{event_id}/context?lines=10`
Просмотр исходного файла вокруг события (по умолчанию ±10 строк) с подсветкой целевых строк `is_target=true`.
Для XML JTL возвращает `422`: у таких событий `line_start`/`line_end` — порядковый номер sample, а не номер строки файла.

---

### Корреляция и Временная шкала

#### `GET /api/correlations/{request_id}`
Выборка всех событий, связанных с заданным Request ID по всем источникам, с вычислением временного разброса `time_span_ms` и списком задействованных систем.
```json
{
  "request_id": "demo-7f31a2",
  "total": 3,
  "time_span_ms": 760,
  "sources": ["sample-app.log"],
  "items": [...]
}
```

#### `GET /api/timeline?start_ms=...&end_ms=...&buckets=40`
Агрегированная плотность событий по источникам для визуализации дорожек активности без перегрузки DOM.

## 5. Запуск на Windows 11

### 1. Подготовка виртуального окружения
```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -r requirements-dev.txt
```

### 2. Запуск приложения
```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8765
```
Откройте браузер по адресу: [http://127.0.0.1:8765](http://127.0.0.1:8765).

### 3. Запуск тестов
```powershell
pytest backend/tests -v
```

### 4. Запуск замеров производительности
```powershell
python backend/benchmark.py
```

## 7. Ограничения текущей версии и планы развития

1. **Фоновые задачи в памяти**: состояние прогресса импорта хранится в оперативной памяти процесса сервера и не сохраняется при аварийном завершении процесса.
2. **Часовые пояса**: несинхронизированные часы распределённых машин не корректируются автоматически. В будущем планируется механизм ручной поправки смещения времени (time offset) для каждого источника.
3. **Объём данных > 2 ГБ**: для комфортной работы с индексами более 5–10 ГБ рекомендуется периодическая очистка старых выборок (`PRAGMA vacuum`).
